# 1.29.0 plan: Projects in Pocket Code

> Phase 1 of moving the work-results features (Projects, then Documents) out of Mission
> Control and into Pocket Code. Written 2026-10-09 from Brad's direction after a
> conversation with Damon. This is a plan, not a record of shipped behavior; the
> [workspace guide](../workspace-guide.md) describes what is live.

## Why

Projects and documents are the direct result of work done in Pocket sessions, so they
belong beside the sessions. Mission Control becomes an operations console (Panel, Ari,
Gil, Schedules, Activity, App setup) and stops owning them.

Projects must work for **any** install of the public repo: no Mission Control, no second
service, no second hostname, no Google account, no email. Data lives in Pocket's data
directory and is served by Pocket's own process. Brad's install is one deployment of the
generic feature, not a special case.

Later phases, not in this release: Documents (library, sandboxed viewer, private/public and
share links, agent drop-in; opens as a tab, beside a conversation, or in the device's own
viewer, using the view mechanism this release builds), the Mission Control cleanup, and a possible "run this prompt
on a schedule" feature that would attach to a project. Google Drive is **not** planned.
There is no separate Schedules tab: a project's reminders and automations appear in the
Projects area (the Scheduled view) and on the project card.

## What stays the same

The Mission Control board's model is kept. Brad's HARD-RULES reference it and it is well
shaped:

- **Explicit enrollment only.** A project is tracked when the user says so or presses
  Track. Starting a session, changing files or leaving work unfinished never creates a
  card. Agents keep the `--requested` flag; nothing is enrolled by inference.
- **One card per project.** States `active`, `waiting`, `done`. Remaining steps are a
  checklist on the card, not separate cards.
- Summary ("where we left off"), next step, waiting-for, directory, link, notes and
  history. Reminders per project or per task. Finishing stops reminders; reopening does
  not restore them. Stale edits are rejected with the current card.

## What is new

**Projects link to sessions.** A card lists the sessions that worked on it, with the same
live status marks as the session rail (running ember, amber needs-you, green unread reply,
red failed). From a session's options you can *Track as project* (card takes the session's
directory and links the session) or *Add to project*. The CLI takes `--session`. This is
the reason to move the feature rather than port it: Mission Control could never do it.

**Scheduled view.** One list across all projects of every open reminder, due first. Only
things Pocket itself owns appear there, so the list is complete about what it shows and
honest about what it does not see.

## A. Decisions that shape the design

Settled with Brad on 2026-10-09: reminders go by web push **plus the optional hook
command** (A3), the Projects list lives behind a **Sessions · Projects switch in the rail
head** (A6), and projects open as a **tab, beside a conversation, or full-screen on the
phone**, with no *Open app* mode (A2). The reasoning stays below for the record.

1. **Storage: a JSON file, not SQLite.** `{DATA_DIR}/projects.json`, written with the
   existing atomic tmp-and-rename helper, mode 0600, with a per-project `revision` for
   stale-edit rejection. Pocket keeps all its state this way and has no database;
   `node:sqlite` is still experimental on Node 22. Brad's whole board is 6 projects and
   65 tasks. History is capped per project (200 entries) so the file stays small.
2. **Feature flag, off by default.** `projects: boolean` in `pocket-settings.json`
   (server-side, per install) with a Settings → Tools → Projects row. When off, the
   routes return 404 and nothing shows in the UI. Per-browser preference: open projects
   as a *tab* or *beside* the conversation. The *Open app* mode from the original idea is
   dropped for Projects because there is no longer an external app for them.
3. **Reminder delivery: web push plus an optional hook command.** An in-process scheduler
   checks due reminders every minute and sends one push per reminder through the existing
   `pushNotify` path (deep link `/#/projects/<id>`), recording `notifiedAt` so a restart
   never repeats it. Installs without VAPID keys still see due reminders in-app with a
   badge. **Optional:** `POCKET_REMINDER_HOOK=<command>` runs a command with the reminder
   as JSON on stdin, so any install can add email, Slack or anything else without Pocket
   knowing about mail. Brad's box would use it to keep email reminders. *Decided: push
   plus hook.*
4. **Agent CLI authenticates with a loopback token.** Agents must write to the board
   without the browser password. At boot the server writes `{DATA_DIR}/cli-token` (0600)
   and accepts it as a bearer token **only** on `/api/board*` **and only** from loopback.
   The CLI never touches `projects.json` directly, so there is one writer.
5. **Route names.** Pocket already uses `/api/projects` for working-directory discovery on
   the New session screen, so the board API is `/api/board` and `/api/board/act`, the
   same names agents already know from Mission Control.
6. **Rail placement.** The desktop rail head gets a two-way switch, *Sessions · Projects*,
   so Projects uses the rail's width, filters and resize behavior instead of adding a
   second column. On the phone, Projects is a button in the session-home header beside
   New. *Decided: the rail switch.*
7. **Mission Control during the switch.** Import once, then Mission Control's Projects tab
   shows "Projects moved to Pocket Code" with a link, and its `project-reminders.timer`
   is disabled once Pocket's push or hook reminders are proven for a few days. The two
   stores are never written in parallel.

## B. Data model

`projects.json`:

```json
{ "version": 1, "projects": [ {
  "id": "…", "name": "…", "summary": "…", "next": "…", "waitingFor": "…",
  "status": "active | waiting | done", "directory": "/abs/path", "link": "https://…",
  "sessions": ["<claude id>", "cx:<codex id>"],
  "created": "ISO", "updated": "ISO", "verified": "ISO", "revision": 7,
  "enrollment": "requested | suggested",
  "tasks": [ { "id": "…", "text": "…", "done": false, "created": "ISO", "updated": "ISO" } ],
  "reminders": [ { "id": "…", "task": null, "label": "…", "dueAt": "ISO", "state": "open | done | cancelled", "notifiedAt": null, "updated": "ISO" } ],
  "history": [ { "at": "ISO", "actor": "ui | cli | import", "action": "…", "detail": "…" } ]
} ] }
```

Text fields are limited as the current store limits them (600 characters; task text 300).
`link` must be `http(s)`. Session ids are validated against the existing id patterns.
The file is the only writer surface; every change goes through the store module
(`projects.mjs`) with the same serialize-then-rename discipline as the other stores.

## C. API

All routes require the browser cookie or the loopback CLI token, and return 404 when the
feature is off.

- `GET /api/board` → `{ projects, now, push: { enabled }, scheduled: [reminders due-first] }`.
  `?dir=<path>` also returns `match`: the project whose directory contains that path, for
  the CLI's "which project is this".
- `POST /api/board/act` with `{ action, project, expected_revision, … }`. Actions:
  `track`, `update`, `task-add`, `task-update`, `remind`, `reminder-dismiss`, `note`,
  `link-session`, `unlink-session`. Stale `expected_revision` → 409 with the current
  card. `update status=done` cancels open reminders; `status=active` on a done card does
  not restore them. Every action appends history with the actor.

## D. UI

Design brief (Operate mode, pinned per DESIGN.md): variance 3, motion 1, density 6.
Existing tokens only. The card is a document, not a dashboard tile; the rail and sheets
reuse the session-home patterns. No new colour: project state uses the words
Active/Waiting/Done, not a palette, and reminder due-ness uses the existing amber.

Routes: `#/projects`, `#/projects/<id>`, `#/projects/scheduled`.

- **Projects list.** Grouped Active, Waiting, Done (collapsed). Each row: name, next
  step, a due-reminder label when one is due, and the linked sessions' status marks.
  Track button opens the editor (name, summary, next, directory, link).
- **Project card.** Summary, next step, waiting-for; checklist with add, check, reopen,
  edit; reminders with *Remind me*, *Remind later*, *Dismiss* (armed confirm, as today);
  linked sessions with *Open* and *Open beside*; notes; history collapsed; *Finish
  project* (armed) or *Resume project*. Done cards are read-only except Resume.
- **Scheduled.** All open reminders across projects, due first, each linking to its card.
  Reachable from the Projects list head and from the rail switch's badge.
- **From a session.** Session options sheet gains *Track as project* and *Add to project*
  (a picker of active projects). Tracking from a session fills the directory from the
  session's working directory and links the session.
- **Tabs (desktop).** A project opens as an open tab in the same strip as sessions, the
  way a session does: same close control, pinnable, in the Alt [ / ] order, and the tab
  mark is the due-reminder count instead of a session status. Selecting it shows the card
  in the main area where a conversation would be; the session-scoped dock (Results,
  Queue, Git) is hidden there. The Projects list and the Scheduled view can be tabs too.
  Tab keys are routes (`projects`, `projects/<id>`, `projects/scheduled`) stored
  alongside the session tabs. On the phone there are no tabs; views open full-screen.
- **Split view.** A pane may target `projects`, `projects/<id>` or `projects/scheduled`.
  *Open beside* gains a Projects entry. Panes are already full Pocket instances, so this
  is a change to the pane validator and the chooser, not a new frame type.
- **Three ways to open, like a session:** a tab, a pane beside the conversation, or
  full-screen on the phone. The *Open app* mode is not needed for projects because there
  is no longer an external app for them.
- **Built as generic views, not a Projects special case.** Tabs and panes key on routes,
  so Phase 2 adds Documents (the library and any single document) to the same tab strip
  and the same pane chooser without touching that code again. Documents also get an
  *Open app* mode, which means opening the document itself in its own browser tab or the
  device's viewer (a PDF in the phone's PDF app); that mode shows only where an external
  target exists.
- **Badges.** The rail switch and the phone header button show the count of due
  reminders. One push per due reminder, deep-linked to the card.
- **Settings → Tools.** Projects On/Off (server-wide) with a one-line explanation; *Open
  projects* As a tab / Beside the conversation (this browser).
- **Phone.** Full-screen list and card like the session home; editors in bottom sheets;
  44px targets; no horizontal overflow at 360.

## E. Agent CLI: `pocket-board`

Shipped in the repo (`scripts/pocket-board.mjs`, exposed as a `bin` in `package.json`) so
any install's Claude Code or Codex sessions can keep a card current. It mirrors the
current `board` verbs so Brad's rules and skill move over with a name change:

```
pocket-board track --requested --name "…" [--summary …] [--next …] [--dir …] [--link …] [--session <id>]
pocket-board status [--all] [--json]           # current directory's project by default
pocket-board update [--name|--summary|--next|--waiting-for|--link|--status]
pocket-board task add|done|reopen|edit <value> [--text …]
pocket-board remind --at "YYYY-MM-DDTHH:MM" [--task <id>] [--text …]
pocket-board dismiss <reminder>
pocket-board note "…"
pocket-board link-session <id> | unlink-session <id>
pocket-board import --from <board.sqlite3 | status.json>   # one-time
```

Times without an offset use the install's time zone (`POCKET_TZ`, default the system
zone). The CLI talks to `http://127.0.0.1:<port>/api/board` with the loopback token and
never opens the data file.

## F. Import of Brad's board

One-time `pocket-board import` reads the Mission Control SQLite store (or `board status
--all --json`) and maps 1:1: projects, tasks, open reminders, history, `enrollment`,
`revision`. Six projects today. After import, Mission Control's board is frozen (decision
A7). Verification: every card, task and open reminder matches by id; a diff is printed.

## G. Security and limits

- Off by default; 404 when off; nothing about the feature is reachable unauthenticated.
- CLI token: loopback only, bearer only on `/api/board*`, file mode 0600, rotated at boot.
- Field limits and `http(s)`-only links as today; all text rendered as text, never HTML.
- History records the actor so a CLI change and a UI change are distinguishable.
- No per-user model: one install, one board, like the rest of Pocket.

## H. Tests and verification

- **Unit:** store (revision conflicts, done cancels reminders, resume does not restore,
  per-project history cap, atomic write), scheduler (due detection, `notifiedAt`
  idempotence across restart, hook invocation with JSON on stdin), import mapping from a
  fixture, CLI argument parsing and time-zone handling.
- **HTTP:** feature off → 404; token accepted only from loopback and only on the board
  routes; action validation; 409 shape; `?dir=` matching.
- **Browser (390 and 1440):** list, card, track from the list and from a session, checklist
  and reminder flows, Scheduled view, project tabs (open, pin, cycle, close, due mark),
  split pane target, due badge, Settings toggle hides
  and shows the feature; axe on every new surface; impeccable detector on the rendered
  views.
- **Docs:** workspace guide section, README feature line, DESIGN.md "Projects (1.29)",
  changelog, in-app release notes, screenshots regenerated. Release 1.29.0 / asset build 69.

## I. Rollout on Brad's box

1. Deploy with the feature off; enable in Settings; set `POCKET_REMINDER_HOOK` to the
   existing email path if decision A3 keeps email.
2. Import; verify the diff; freeze Mission Control's board.
3. Update HARD-RULES and the `project-board` skill to `pocket-board`.
4. After a few days of correct reminders, disable `project-reminders.timer`.
5. Damon's server: deploy normally; the feature stays off unless he turns it on.

## Out of scope for 1.29.0

Documents, Google Drive, a Schedules tab, scheduled prompts, multi-user boards, email
inside Pocket, and any Mission Control code changes beyond the "moved" banner.
