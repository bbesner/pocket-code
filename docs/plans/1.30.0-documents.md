# 1.30.0 plan: Documents in Pocket Code

> Phase 2 of moving the work-results features out of Mission Control. Phase 1 (Projects,
> 1.29.0) shipped on 2026-10-09; this plan was written the same day from Brad's direction.
> A plan, not a record of shipped behavior: the [workspace guide](../workspace-guide.md)
> describes what is live.

## Why

Documents are the other thing that comes out of sessions: reports, dashboards, PDFs,
images, exports. Today they live in Mission Control's Documents tab, with a Brad-only
library, a staff gateway and public links. They belong beside the sessions and projects
that produced them, and they must work for **any** install of the public repo: no Mission
Control, no second service, no second hostname, no Google account. Google Drive is out
entirely (Brad, 2026-10-09).

Same shape as Projects: off by default, data in Pocket's data directory, served by Pocket's
own process, and opened the way a session is opened: as a tab, beside a conversation, or
full-screen on the phone, plus one mode a project does not have, **the device's own viewer**.

## What a document is

A file that came out of the work, with a little metadata Pocket keeps beside it:

- the file itself, in the documents folder (`POCKET_DOCUMENTS_DIR`, default
  `<data dir>/documents`);
- a record in `<data dir>/documents.json`: id, file name, title, kind, size, when it was
  added and by whom (ui, cli, session, import), the session and project it came from,
  visibility, and share tokens.

Kinds, by extension: `html` (reports and dashboards), `pdf`, `md`, `txt`, images (`png`,
`jpg`, `jpeg`, `gif`, `webp`), `csv`/`tsv`, `json`, `docx`/`xlsx`/`pptx` (download only),
`mp4`. Anything else is refused on the way in.

## How documents get in

1. **An agent keeps a file.** `pocket-docs add <path> [--title …] [--project <id>] [--session <id>] [--visibility private|link|public]`
   copies the file into the documents folder and records it. Same loopback token as
   `pocket-board`; only `/api/documents*` routes accept it. With Documents on, agents started
   by Pocket get one instruction line: when a deliverable is for the user to read, keep it with
   `pocket-docs add`, linked to the session (and to the directory's project when there is one).
2. **Pocket offers to keep a session's results.** The Results panel already lists the files a
   session wrote or linked (`results.mjs`). Each of document kind gains **Keep as document**,
   which copies it in with the session and project links filled.
3. **You upload one.** From the library, on the desktop or the phone (the existing upload
   path with the same 30 MB limit, saved into the documents folder instead of the uploads folder).
4. **Files dropped straight into the folder** are adopted on the next listing as private
   documents with no session. This keeps the existing convention on Brad's box ("drop the
   `.html` into the folder and it appears") working unchanged.

One writer for the metadata: the Pocket server. The folder scan only ever *adds* records
for files it does not know; it never changes visibility.

## Viewing

- **HTML renders sandboxed.** A document's HTML is served inline from `/api/documents/<id>/raw`
  with `Content-Security-Policy: sandbox allow-scripts allow-popups allow-downloads` (no
  `allow-same-origin`) and shown in an iframe with the same `sandbox` attribute. Scripts in a
  dashboard still run; nothing in it can read Pocket's cookies, storage or API. This is the
  same rule Pocket already applies to session artifacts, relaxed only enough for dashboards
  to work.
- **PDFs** render in the browser's viewer inside the same frame; **images**, **Markdown** and
  text render natively (Markdown through Pocket's own renderer, like a reply); **CSV/TSV**
  as a table; Office files and video offer **Open in your viewer** and download.
- **Open modes.** A document is a view like a project: `#/documents/<id>` opens as a tab in
  the strip, beside a conversation, or full-screen on the phone. **Open in your viewer**
  navigates the device to the raw file (PDFs open in the phone's PDF app, images in the
  photo viewer), and **Download** saves it. These two are the "open app" modes.

## Sharing

Three visibilities, all served by Pocket on its own hostname:

- **Private** (default): behind the Pocket login, like everything else.
- **Link**: an unguessable signed URL, `/share/<token>`, optionally expiring, revocable
  (revoking makes a new token; the old one answers 404). The page it serves is the document
  only, with the same strict headers as the public path.
- **Public**: `/files/<name>` with no login, exactly the path Mission Control's public links
  use today, so existing public URLs keep working once the hostname routes to Pocket.

Public and link responses carry `no-store`, `nosniff`, `noindex`, `frame-ancestors 'none'`
and, for HTML, the sandbox policy above. The library shows each document's visibility and
its share URL, with copy.

**Brad's staff tier** (five documents today, verified `@techprosecurity.com` accounts at
docs.bbesner.com) is not a product feature. It becomes: those documents get *Link*
visibility, and Cloudflare Access stays in front of `docs.bbesner.com`, which routes to
Pocket's share path. The link is unguessable *and* behind Google sign-in. Nothing in the
product knows about Access.

## Ties to the rest

- A document knows its session and its project. A project card lists its documents; a
  session's Results panel shows which results were kept; the library filters by project.
- The Projects view mechanism (tabs, panes, phone) is reused as is: Documents adds view
  ids `documents`, `documents/<id>`.
- Settings → Tools gains **Documents** On/Off (server-wide) and the default open mode for
  this browser, beside the Projects rows.

## A. Decisions that shape the design

1. **Documents folder on Brad's box: point Pocket at the existing folder.**
   `POCKET_DOCUMENTS_DIR=/home/ubuntu/services/webhook-server/public` (424 files, 2.8 GB,
   337 of them HTML). No copy, no move, nothing breaks while the switch happens; the
   metadata import reads `dashboard-files-meta.json` once (281 private, 132 public, 5
   staff). *Recommended.* The alternative, moving 2.8 GB into Pocket's data directory, buys
   nothing.
2. **Public URL continuity.** Route `webhooks.bbesner.com/files/*` to Pocket's `/files/<name>`
   once the import is verified, so the 132 public links keep working without a redirect.
   Until then Mission Control's gateway keeps serving them from the same folder, which is
   safe because Pocket only adds records and never moves files. *Recommended.*
3. **Staff tier → share links behind Access** (above). *Recommended* over teaching Pocket to
   verify Cloudflare JWTs, which no other install needs.
4. **Scope of 1.30.0.** Library, viewer, private/link/public, `pocket-docs`, Keep as document,
   upload, project and session links, import, Settings. *Recommended: all of it in one
   release*, because the pieces are small individually and the migration needs link sharing
   on day one. If it has to split, link sharing and the agent instruction go second.
5. **Removing a document.** Mission Control deletes outright. Pocket moves the file to
   `<documents dir>/.trash/` and keeps the record for 30 days, then purges; the library has
   a Restore for that window. *Recommended.* Agents are not offered delete at all.
6. **Rendering budget.** HTML documents up to 10 MB render inline; larger ones offer Open in
   your viewer and Download. Video never renders inline on the phone (data), it offers the
   viewer.

## B. Data model

`documents.json`:

```json
{ "version": 1, "documents": [ {
  "id": "…", "file": "report-2026-10-09.html", "title": "…", "kind": "html", "size": 12345,
  "added": "ISO", "addedBy": "ui | cli | session | import | folder", "updated": "ISO",
  "session": "<id> | null", "project": "<project id> | null",
  "visibility": "private | link | public", "share": { "token": "…", "expiresAt": "ISO | null" } | null,
  "trashedAt": "ISO | null"
} ] }
```

File names are made safe on the way in (as uploads are today) and must be unique in the
folder; a clash gets a short suffix. Titles default to the file's `<title>` for HTML, the
first heading for Markdown, else the file name. Records are capped at 5,000; the folder scan
stops adopting beyond that and says so.

## C. API

All routes 404 while the feature is off. Browser cookie, or the loopback token on
`/api/documents*` only.

- `GET /api/documents?project=&q=` → the library (records plus a folder scan that adopts
  unknown files), newest first.
- `POST /api/documents` (multipart or raw with `x-filename`, like upload) → add from the UI.
- `POST /api/documents/add` `{ path, title, project, session, visibility }` → the CLI's
  copy-in; the path must be a readable file under the user's home, of a known kind.
- `POST /api/documents/keep` `{ session, path }` → Keep as document from Results (the
  path must be one of that session's results).
- `POST /api/documents/<id>` `{ title, project, visibility, expiresAt }` → edit;
  `{ action: 'reshare' }` → new token; `{ action: 'trash' | 'restore' }`.
- `GET /api/documents/<id>/raw` → the file, inline, sandboxed when HTML (login required).
- `GET /files/<name>` → public documents only; `GET /share/<token>` → link documents
  (and public ones), expiry enforced; both unauthenticated, strict headers.
- `POST /api/documents/import` → one-time import of Mission Control's metadata file.

## D. UI

Design brief (Operate, pinned): variance 3, motion 1, density 6. Existing tokens; the
library rows reuse the session-row voice; the viewer is a frame with Pocket's bar above it.

- **Library** (`#/documents`): search box, filter chips (All, this project when opened from
  a card, kind), rows with a kind glyph, title, when and from what (session title, project
  name), visibility word. Upload button. Trash as a collapsed group with Restore.
- **Document** (`#/documents/<id>`): the bar shows the title and the project; the frame fills
  the view; a row of chips: Open in your viewer, Download, Share (visibility sheet with the
  URL and copy, expiry for links, reshare), Project (set or open), Session (open), Rename,
  Remove (confirm).
- **From a session:** Results panel rows of document kind gain **Keep as document**; kept ones
  show "Kept" and open the document.
- **From a project card:** a Documents section listing the project's documents; the editor
  can attach an existing one.
- **Rail switch** gains Documents as a third segment only on wide rails (≥ 320 px): Sessions ·
  Projects · Documents; on narrower rails the Projects segment's menu offers Documents.
  Phone: a Documents chip on the session home beside Projects.
- **Tabs, panes, phone**: as Projects, with view ids `documents` and `documents/<id>`.
- **Settings → Tools**: Documents On/Off; Open documents: As a tab / Beside the conversation.

## E. `pocket-docs` CLI

`scripts/pocket-docs.mjs` (bin `pocket-docs`), same token and conventions as `pocket-board`:

```
pocket-docs add <path> [--title …] [--project <id>] [--session <id>] [--visibility private|link|public]
pocket-docs list [--project <id>] [--json]
pocket-docs share <id> [--expires 7d|30d|none]      # prints the URL
pocket-docs set <id> [--title …] [--project <id>] [--visibility …]
pocket-docs import <dashboard-files-meta.json>       # one-time
```

The HARD-RULES "Review deliverables" rule on Brad's box then reads: HTML and other review
copies go in with `pocket-docs add` (or into the documents folder) and the message to Brad
links the document in Pocket Code.

## F. Import of Brad's documents

`pocket-docs import` reads `dashboard-files-meta.json`: `visibility: public` → public,
`private` + `access: techpro` → link (new tokens, printed so the five staff links can be
replaced), `private` → private; every file in the folder without a record is adopted as
private. Nothing moves. Verification prints counts by visibility and lists any file the
metadata names that is missing from the folder.

## G. Security

- Off by default; 404 while off; the token opens only the documents routes, loopback only.
- HTML never executes under the app origin: sandbox CSP on the response and on the frame;
  `nosniff`; inline rendering only for known kinds; everything else downloads.
- Public and link paths serve exactly one file per request from the documents folder, by
  record, never by path; no directory listing; `noindex`; `no-store`.
- Share tokens are 32 random bytes, stored hashed; expiry checked on every request.
- Paths accepted by `add` and `keep` are resolved with `realpath`, must stay under the home
  directory and outside dot-directories (the artifact rule), and must be regular files.
- The folder scan ignores dot-files and `.trash`.

## H. Tests and verification

- **Unit:** store (adopt, add with name clash, visibility changes, share token hashing and
  expiry, trash/restore/purge, caps), title extraction, import mapping from a fixture
  metadata file, kind detection.
- **HTTP:** off → 404; token scope; raw with the sandbox header; `/files` only for public;
  `/share` expiry and revocation; `keep` refuses a path that is not a result; `add` refuses
  dot-dirs and unknown kinds; import counts.
- **Browser (390 and 1440):** library, viewer for an HTML and a Markdown fixture (the HTML
  one proves the frame cannot reach the parent), share sheet, Keep as document from Results,
  project section, tabs, split pane, Settings, phone; axe on every new surface; detector.
- **Docs:** workspace guide, README (feature line, `POCKET_DOCUMENTS_DIR`), DESIGN.md,
  changelog, release 1.30.0 / asset build 70.
